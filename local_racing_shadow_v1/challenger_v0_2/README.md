## v0.2.0-candidate scoring contract
純粋関数 `scoring.mjs` は、v0.1の immutable prediction のみを読み取り、結果・払戻・オッズに触れない。現行スコアのレース内正規化に、探索的な少数の事前固定仮説を加える。調整値は **機械学習済み係数ではない**。

```
base_z = (v01_evidence_score - race_mean_score) / max(race_sd, 0.75)
candidate = base_z + pace_delta + rotation_delta

pace_delta:
  leading_count <= 1 and style=先行: +0.14
  leading_count >= 5 and style=先行: -0.16
  leading_count >= 5 and style=差し・追込: +0.08
  leading_count in [3,4] and style=先行: -0.06
rotation_delta:
  days_since_last > 90: -0.18
  46..90: -0.07
  1..6: -0.05
  else: 0
```

- 同点は馬番の昇順で決定。非出走馬は予想順位から除外。
- ばんえい競馬は別モデル準備まで除外し、未対応を明記。
- 騎手、斤量、枠、クラス、走破時計、馬場状態、オッズは保持できるが**推奨点数には加算しない**。誤った未検証係数で改善したと偽装しないため。
- v0.1の元点に既に同距離実績が含まれるため、v0.2で重複加点しない。
- predictソースに結果情報が混じる、出走馬不正、発走前cutoff不在、直近履歴が当日以降の場合は拒否。
- 係数は固定JSON内容のSHA256を計算して全出力に記録。変更は別candidate版として再試験する。

## 実行方式
**A: 研究用リプレイ**（過去データを再採点するが、発走前の新規予想として扱わない）

```bash
node --test local_racing_shadow_v1/challenger_v0_2/test.mjs
node local_racing_shadow_v1/challenger_v0_2/evaluate.mjs
node local_racing_shadow_v1/challenger_v0_2/evaluate.mjs 2026-10-14
```

- v0.1 prediction と公式 result の不変証明付き照合が可能なレースのみ比較。
- 比較は top1勝数、top1の3着以内数、着順の改善・悪化・同点、開催場別件数。
- この数字を用いて候補係数を調整した場合、同じ日付の再集計結果は独立検証にならない。

**B: 今後の実レースでの前向き並走**（既存v0.1を先にGitHubへコミットした後に実行）

```bash
node local_racing_shadow_v1/challenger_v0_2/record_forward.mjs YYYY-MM-DD
# 生成した challenger_v0_2/predictions/ の新規ファイルだけ別コミット
node local_racing_shadow_v1/challenger_v0_2/audit_forward.mjs YYYY-MM-DD
```

- `record_forward` は当日のJSTのみ許可。予定発走10分前を過ぎたレースは作成せず blocker にする。
- **元predictionがGitHubに初回コミット済みで、元のbyte列から一切変わっておらず、その時刻が発走前であること**を検証。
- Challengerも別の新規ファイルに書き、上書き不可。コミット成功前は `PENDING_GITHUB_COMMIT_AUDIT` であり「固定完了」と呼ばない。
- `audit_forward` は自分自身のコミット時刻を含め発走前時刻と元データの不変性を再検証。Actions成功表示だけで完了にしない。
- 現段階は**コマンド実装のみ**で、既存GitHub Actionsや公開サイトへの自動接続・自動運用は未実装。承認後に別CI/本番導線を追加する。
- 予想と結果は分離し、resultを観測した後に前向き予想の差替え禁止。

## 比較・検定設計
| 項目 | 仕様 |
| --- | --- |
| 母集団 | 発走前proof有効の同一レース・同一出走馬 |
| 基準1 | 現行v0.1、完全同条件 |
| 基準2 | 発走前に取得し固定した単勝オッズ1番人気（未取得なら計測不能） |
| 評価 | 本命勝率、3着内率、本命着順誤差、候補の改善/悪化、競馬場・距離・頭数・開催日 |
| 確率・ROI | レース前オッズと払戻、**検証用の確率較正モデル**を用意できるまで未評価 |
| 誤差評価 | ペア比較 + 開催日単位のクラスターブートストラップ、区間推定 |
| 順序 | 研究リプレイを探索 → 将来レースは事前固定 → 未学習日付で判定 |
| 欠損 | 予想漏れ・証明不成立・競走中止などを明示し、分母の恣意的除外禁止 |
| ばんえい | 専用プロトコルを別途設計 |

## 次の実装（v0.2完成に必要）
1. PRE-RACE捕捉を全開催場に対して継続。Shadow開始後に締め切り時間が足りないレースはギャップとして保持。
2. 過去走の**クラス・着差・距離・馬場・走破時計・通過順・頭数**を発走前証跡付きで拡充し、時計や相手関係の尺度を作る。
3. 同日バイアスは当該レースより前に公表済みの公式情報だけで推定し、いつ観測したかを記録する。
4. その後に騎手×条件、相対斤量、枠×脚質×頭数、ローテと過去走信頼度を個別にアブレーション検証する。
5. 購入判断用に予想時点のオッズ全券種と時刻、払戻を別データとして保存し、複数点セット最適化を後段に分離。
6. 日付ベースの時系列検証を通し、モデル係数改定は事前登録、新バージョン。現行v0.1のまま日次収集も維持。

## 昇格条件（提案）
- テスト・データ契約・GitHubの発走前proof・未改変監査が全対象で成功し、coverage gapが説明可能。
- 最低500レース、10以上の異なる開催日、3場以上の**独立した前向き評価**を最初の審査目安とする（統計区間が広ければ継続）。
- ベースラインより本命勝率/3着内率/着順誤差の少なくとも複数で安定改善し、会場別の著しい劣化がない。95%不確実性区間を示す。
- 人気1位との比較・期待値・回収率は、発走前オッズと払戻が揃ったレースだけ別判定。ROIのプラスは保証しない。
- まず **地方研究用モデルの正式化** だけ承認対象とし、JRA採用は別のJRA E2E・人手承認。JRA資産には変更しない。
