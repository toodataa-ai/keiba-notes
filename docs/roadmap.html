IMPROVEMENT PHILOSOPHY / ROADMAP / GOVERNANCE

改善は、足すことではない。
測って、捨てて、残すこと。

このページは「次にどんな機能を付けるか」の一覧ではありません。予想精度を高めるために、何を仮説として立て、どう検証し、どこまで自動化し、どの条件を満たしたら本番へ採用するか。その判断基準を、これまでの改善履歴と今後の方向性をつないで公開する読み物です。

目標は、ルールを増やし続けることではありません。予測時点で使える情報を取りこぼさず、結果リークを防ぎ、改善したつもりの改悪を検出し、効いた部分だけを残すことです。

CORE THESIS

予想ロジックは「正しそう」ではなく「比較できる」状態にする

競馬予想には、もっともらしい説明をいくらでも後付けできます。だから本システムでは、改善案を思いついた時点をゴールにしません。変更前と変更後を同じ条件で比較し、改善しなければ捨てます。実際にACI v1.1では、コース需要型の過去走ACIへ機械的に置き換える案や、再現性ペナルティを直接ランキングへ差し引く案はバックテストで悪化したため不採用にし、解釈レイヤーと再現信頼度だけを部分採用しました。

02

これまでの改善は、一本の流れにつながっている

「新しい機能を増やした歴史」ではなく、「誤差の原因を分解してきた歴史」です。

実装済み / v2.8まで

能力と価格を分離

STEP1で能力・適性を評価して印を固定し、STEP2でのみオッズと期待値を扱う二層構造を確立。同条件直接実績、条件変化による復活候補、時計・位置・進路のバイアス分離も導入。

実装済み / v2.9

「見た」から「評価へ伝播した」へ

当日馬場情報の鮮度、直接実績・復活候補のABC評価と印への伝播、基礎能力と今回期待性能の分離、複数の小さな不利が重なる複合リスクを監査。

実装済み / v3.0

ルールを増やさず整理

意味を変えずに要件IDで再構成。v2.9の要件群をカバレッジ監査し、欠落ゼロを確認。以後は同義ルールを追記せず既存要件へ統合する方式へ移行。

実装済み / v3.1

ACIと再現信頼度を部分採用

上がり3Fを絶対時計でなく相対値＋4角位置補正で扱い、競馬場の要求特性を解釈レイヤーに追加。能力そのものと「今回も出せる確からしさ」を分離。

検証中

馬場20モデルを独立育成

10競馬場×芝/ダートを別モデルとして管理。既存中山・阪神を壊さず、東京・京都などをStage A Candidateまで進め、本番接続は承認制。

検証中

E2Eで予想全体を比較

部分指標ではなく、情報取得→STEP1→STEP2→結果→採点までを同一条件で比較。Grade B歴史再現でパイプラインを先に壊し、Grade A実戦データを積む。

共通している考え方：「新しい情報を加えれば精度が上がる」とは考えません。情報を分解し、評価の伝播を確認し、結果リークを防ぎ、改善効果を測定してから採用します。
03

改善は、レースごとの循環と、本番採用のガードを分ける

トップページで示している基本思想を、ここでは実際の運用レベルまで展開します。

まず、日々の基本サイクル

予想を出して終わりではなく、結果を記録し、外れ方まで検証して、次の改善へつなげます。変更内容は版ごとに残し、次のレースで再検証します。

1予想する最新プロンプトと同じ評価軸で全頭を分析
2結果を記録印・着順・馬券収支を予想時の情報とセットで保存
3反省・誤差分析見落とし、過大評価・過小評価、展開差などを分解
4プロンプト改良再発防止ルールを検討し、変更理由と内容を版管理
5次レースで再検証改良版を適用し、精度・回収率・誤差の変化を継続観測

改善案を本番へ入れるときは、さらに厳しくする

日々の反省で見つけた改善案を、そのまま本番へ入れるわけではありません。仮説化し、既存本線から隔離して検証し、候補化・承認・実戦監視まで通します。

1. 誤差を観察外れ方・不足情報を分類
2. 仮説化何を変えれば改善するか限定
3. 隔離実装既存本線を壊さず追加
4. 検証時系列・LOYO・E2Eで比較
5. Candidate数値基準を満たした候補
6. 承認本番接続は人が判断
7. 監視実戦で劣化・偏りを確認

非破壊を優先

新モデルは追加レイヤーとして育て、既存Validatedモデルや本番ルータを勝手に置換しません。

自動化はCandidateまで

機械判定で候補を作ることは自動化しても、Candidate→Validatedや本番置換は明示承認を必要とします。

単発結果で変えない

一つのレースの的中・外れだけで重みやルールを変えず、複数ケースで再現する誤差かを確認します。

採用しない結果も資産

精度が悪化した案を消さず、なぜ棄却したかを残すことで、同じ失敗を別名で繰り返さないようにします。

04

最優先は、馬場予測を「全10場で使える」から「全10場で検証済み」へ進めること

20モデルを作ること自体ではなく、Stage AとStage Bを別々に検証し、発走時の不確実性を正しく出すことが目的です。

STAGE A

前日・前々日 → 当日朝

競馬場ごとの含水率特性と気象応答を学習し、JRA公式の当日朝含水率を予測します。

  • 競馬場・芝/ダートを独立モデル化
  • Leave-One-Year-Outまたは前向き時系列ホールドアウト
  • MAE / RMSE / ±1pt以内率だけでなく雨天ケースを別監査
  • naive baselineを明確に上回ることを昇格条件にする
STAGE B

朝のJRA実測 → 各レース発走時

ここが今後の重点です。発走時含水率には公式の正解ラベルがないため、架空の教師値を作らず、JRA公式の「良・稍重・重・不良」を確率予測します。

  • 降雨、雨上がり経過時間、気温、風、日照、開催中の変化を入力
  • Log Loss / Brier Score / Calibrationで現行heuristicと比較
  • 雨天遷移日を独立監査
  • 確率分布として予想本体へ渡し、「本線馬場」と不確実性を分ける
DRIFT

季節・改修・開催進行でモデルが古くなることを前提にする

京都改修後のような構造変化、開催後半の傷み、季節差を同一分布として扱いません。Validated後も、期間別誤差を監視して degraded 判定できる設計へ進めます。

MODEL REGISTRY—Validated / 20
BACKTESTING—本番未接続
PILOT—まだ検証不足
05

当日バイアスは「内有利・前有利」で終わらせない

すでに分離した三つのバイアスを、今後は確信度付きの入力へ育てます。

時計速度その日の走破時計が標準より速いか遅いか。高速＝前有利とは限りません。
位置取り逃げ・先行・中団・後方のどこが相対的に残りやすいか。
進路内・中・外、直線の通過位置に偏りがあるか。

今後は、当日何レース観測したか、同じ芝/ダート・近い距離の証拠が何本あるかを使って「バイアスそのもの」と「そのバイアスを信じてよい度合い」を分離します。2レースだけの傾向を強い補正として使うことを避け、時間とともに更新する入力へ進化させます。

06

展開は「Mペース予想」一個ではなく、複数シナリオの確率で扱う

逃げ候補の頭数だけでなく、ハナ意思・競り合い・隊列崩壊の可能性を分けます。

これまでの改善で「先行馬が多い＝ハイペース」と短絡しない方向へ進めてきました。次は、S/M/M-H/Hの一つを断定するのではなく、各シナリオの確率と、そのシナリオごとに得をする馬を持つ構造へ進めます。

目指す形

スロー 15% / ミドル 45% / M-H 30% / ハイ 10%

各シナリオで位置取り、脚の使い方、差し届き確率を再評価。

避ける形

「逃げ馬4頭だからハイ」「逃げ馬1頭だからスロー」と機械的に決定。

騎手の意思、枠、テン速度、近走の逃げ失敗まで見ずに断定しない。

07

生時計・上がり順位から、条件調整された能力表現へ

Time IndexとACIは役割を分け、同じ強さを二重加点しないことが重要です。

類似条件 Time Index

競馬場、走路、距離、馬場、斤量、ペースなどを揃え、生時計の単純比較を避けます。まず同条件直接実績を優先し、その次に近い条件を使います。

ACI

上がり3Fを同一レース内の相対値と4角位置で補正し、鋭い末脚の価値と、そのコースで末脚へどれだけ依存するかを分けて解釈します。

今後は、この二つを一つの総合点へ乱暴に足すのではなく、能力の証拠・脚質適性・コース要求・再現性のどこを説明する指標なのかを固定します。またGrade Bストレステストで露出した、履歴が薄い2歳・3歳馬の成長曲線も独立課題として扱います。

08

「強い」と「今回もその強さを出せる」は別の変数にする

心理を推測せず、客観的な性能変動を再現信頼度として扱います。

ピーク能力条件が噛み合ったときに到達できる上限。
現在値近走、調教、ローテ、条件変化を踏まえた今の能力水準。
再現信頼度近い能力を今回も発揮する確からしさ。ACI等の客観的なばらつきを利用。

再現性が低い馬を一律に減点するのではなく、本命の信頼度、相手候補の幅、シナリオ依存性へ反映します。v3.1で「再現性ペナルティをランキングから直接差し引く」方式を棄却したのは、この思想を守るためです。

09

騎手評価は「有名・上手い」から、条件別の上振れ・下振れへ

騎手格言は入口にすぎず、対象場・走路・距離・脚質・馬質を補正して評価します。

既存の⑧騎手では、格言だけでなく競馬場・走路・距離の実績、全国平均との差、馬との相性、継続騎乗、想定展開への適合を扱います。今後はさらに、馬質に恵まれているから勝っているのか、同等馬質でも結果を上積みしているのかを分離し、条件別の寄与を小さくても再現可能な補正として扱う方向へ進めます。

10

印の精度だけでなく、「確率の正しさ」を測る

期待値評価を強くするには、勝率・3着内率のCalibrationが必要です。

◎○▲が当たったかだけでは、どれほど自信があったのかを評価できません。将来は各馬の勝率・3着内率、馬場状態、展開シナリオの確率をより一貫して出し、Brier Score・Log Loss・Calibration Errorで測ります。

見るもの主な指標理由
能力順位◎勝率、◎3着内率、Top3捕捉率、勝ち馬Top3印率STEP1の純粋な順位品質を見る
確率Brier Score / Log Loss / Calibration「60%と言ったものが本当に約60%起きるか」を測る
馬券ROI、投資額、払戻、収支STEP2の価格判断を見る。ただし分散が大きいので単独判定しない
条件別安定性場・距離・馬場・脚質・人気帯別全体平均に隠れた弱点を見つける
11

E2Eは「当たったか」より、「改善したと言ってよいか」を判定する装置

部分指標だけ改善して全体予想が悪化することを防ぎます。

Grade A

prospective_strict
発走前に予想をGitへ保存し、そのcommit SHAをproofにする正式比較。プロンプト昇格の中心証拠。

Grade B

historical_replay
過去レースを時点情報だけで再構成。パイプライン・盲点・不安定性の発見に使うが、単独で昇格根拠にしない。

Synthetic

CI・計算ロジックの動作確認専用。実予想の成績には一切含めない。

現在は24レースのGrade Bストレステストを通じて、データ欠落、timestamp semantics、version再現性、結果結合、条件別盲点を先に洗い出す段階です。その後、同一レースでbaseline版とcandidate版のGrade Aを積み、十分な共通ケースが揃ってから比較します。

12

プロンプトは、改善のたびに長くしない

v3.0以降は「追記」ではなく「要件IDへ統合」、v3.1は差分モジュール化へ進みました。

ルールが増え続けると、処理時間だけでなく、重要ルールの埋没、同義ルールの矛盾、保守不能化が起きます。そこで今後は、次の運用を続けます。

意味を変えない圧縮

既存要件のカバレッジを監査してから構造整理する。短くするためにルールを落とさない。

差分モジュール

大きな基礎版を毎回複製せず、新規採用部分だけを差分として管理する。

最新版ポインタ

ファイル名順で最新版を推測せず、latest_prompt.jsonを正本として解決する。

変更理由を残す

version、変更点、理由、棄却案、根拠をprompt_historyへ追記し、過去履歴を上書きしない。

13

分析が正しくても、読めなければ品質不足

HTML/PDFの可読性・完全性・検品も、予想プロセスの一部として固定します。

完全版では、A4縦1カラム、1頭1ページ、本文・表とも約13pt、Meiryo UI、ABC評価色、印順の全頭診断、馬場確率・隊列・根拠の明示を維持します。要約版への意図しない縮退、文字の過度な縮小、PDF化による崩れを防ぎ、全ページ画像検品まで含めて「成果物が完成した」とみなします。

今後の可視化：予想PDFだけでなく、サイト側でも「どのモデルを使ったか」「そのモデルはValidatedかPilotか」「どのデータが不足しているか」「どの改善が採用／棄却されたか」を追える状態を広げます。
14

精度向上のために、あえて「やらないこと」を固定する

自由度を増やしすぎると、後付け説明と過学習が増えます。

結果を知った情報を混ぜない発走後の記事、払戻、回顧、将来更新されたデータを予想時点の入力へ逆流させない。
オッズでSTEP1の印を動かさない人気と能力を混ぜない。価格判断はSTEP2に限定する。
生時計を単純比較しない場・距離・馬場・斤量・ペースが違う時計をそのまま能力順位にしない。
発走時含水率を捏造しない公式正解ラベルがない値を教師データとして扱わない。
馬の心理を能力変数にしない「気分屋」「やる気」ではなく、客観的な性能変動と再現性だけを扱う。
単発レースでルールを変えない一回の成功・失敗を一般化せず、複数ケース・条件別に再現するか確認する。
Candidateを自動で本番へ入れない自動化は評価まで。本番接続、Validated化、既存モデル置換は承認制を維持する。
ROIだけで優劣を決めない馬券収支は分散が大きいため、能力順位・確率校正・条件別安定性と併記する。
15

今後は、この順番でブラッシュアップする

精度へ直結しやすく、かつ検証可能なものから優先します。

NOW / 最優先

馬場モデルのStage B検証。東京・京都Stage A Candidateの次に、レース時点の公式馬場状態を教師ラベルにした確率校正を整備。並行して残り競馬場のStage Aデータセットを構築。

NOW / 並行

Grade B 24レースのE2Eストレステスト完遂。精度競争ではなく、リーク・再現性・データ欠落・条件別盲点を洗い出し、Grade A運用を壊れにくくする。

NEXT

当日バイアスと展開の確率化。時計速度・位置・進路の確信度と、S/M/M-H/Hのシナリオ分布を予想本体へ接続。

NEXT

能力・再現性・成長の分離。Time Index / ACIの重複加点を監査し、2歳・3歳の成長曲線、長距離・道悪など条件別の再現性を追加検証。

THEN

勝率・3着内率のCalibrationを本格運用。Grade A共通ケースを蓄積し、印だけでなく確率の質を版間比較できる状態へ。

CONTINUOUS

モデル劣化監視と説明可能性。季節・改修・開催進行によるdriftを検出し、Validatedでも必要ならdegradedへ戻す。サイトでは根拠と不足条件を常時可視化。

「完成版」は作らない。競馬場、馬場、馬、騎手、レース構成は変化します。したがって目指すのは、永遠に固定された最終ロジックではなく、変更を安全に試し、悪化を止め、良化だけを残せる更新系です。
