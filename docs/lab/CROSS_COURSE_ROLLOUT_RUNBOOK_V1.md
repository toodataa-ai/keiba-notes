# LAB v26 コース横展開の標準手順（2026-10-20）

## 基準と不変条件
京都芝2000m内回りの LAB v26 を基準・比較対象に固定する。
既存の SVG、RaceSimEngine、RaceLaneAI、RaceFrameInterpolator、
RaceBroadcastHud、RaceCleanGoalView、RaceSafeRailProjection は流用し、
実結果、正式予想、final_bets、STAGING / production を変更しない。

## 対象
1. 京都芝1400m外回り：同じ京都原 SVG があり、旧LABの外回り図示ガイドがある。まず独立パイロットと安全監査。
2. 東京芝2000m：旧JPEGガイドはあるが原図ベクターはリポジトリにない。原PowerPointのZIPも本環境では取得できなかった。高解像度SVG未確保につき再生不可。
3. 他のJRA：公式コース台帳 race-course-catalog-v1.json に登録。公式仕様があっても図示用原素材と走路抽出が完了していないため再生不可。

## 変えてよいコース固有情報
- 競馬場・芝/ダート・距離・左右/内外回り・スタート/ゴール・距離基準点
- 原画像の出典と原SVGのハッシュ
- 出典を明示したソース画像の内外レール・登録済み曲線
それ以外の馬番の拡大係数・画像専用スロープ・見た目の横方向補正を会場ごとに追加しない。

## 移植ゲート
- レジストリ照合と原SVG読み込み
- 距離地点のアーク長による単調再配置、JRA数値・内外回り一致
- 元画像の芝帯画素確認：5m刻み、6レーンの円盤チェック、逸脱0
- Chrome / WebKitで実況と全体図、1/2/4倍、60秒通過計測、1-3着馬名、全馬時計と着差
- 画面上のシェイク・内ラチ余白・芝帯境界・ゴールカメラを目視確認
- いずれかに失敗したら実走行の起動を止める。検証不足のコースは「完成」と呼ばない。

## 設計上の注意
旧京都外1400の描画登録には過去の個別補正が存在する。今回その既存
ガイドを読み取り専用で利用するが、そのまま共通方式の正式合格とは
せず、次は source image -> inner/outer rails の共通抽出へ置き換える。
原画像を模写したSVGの生成やJPEGの無理な拡大でごまかさない。

## 2026-10-20 実装・検証結果
- 共通部品は race-lab-course-rollout-v1.js（承認ゲート）、race-lab-source-mask-v1.js（緑色走路抽出）、race-lab-cross-course-v1.html / .js（京都外1400独立プレビュー）。元の京都内2000 v26 のコード・原SVGは変更しない。
- **課題の再現**：旧京都外1400走路ガイドをそのまま使うと、原ベクターの緑帯から外れる箇所が多数存在。旧版座標の転用だけでは基準品質を満たさない。
- 共通マスクの実装：既存ガイドを始点の大まかな位置のためだけに使い、うまぽっと原SVGの緑色画素を読み取る。1m刻みの候補緑帯を全区間の動的計画法で接続し、内外の別コースへの飛び移りを抑制。合流部は全区間から得た中央値の芝帯幅を上限に投影する。京都外回り固有の追加offset/slopeはゼロ。
- **一次数値検証**：SVGの緑パス・幅から再構成した近似ラスタでは、京都外1400の5m刻み・6レーン＝1,686点で緑帯外0。全レーン全1mの画面上最大移動量は約0.954px/m、閾値2px/m以内。これは本番ブラウザ描画ではないため最終合格扱いにはしない。
- 共通RaceSimEngineで外回り1400m・架空18頭が全員完走。シード2026、0.08秒刻み、仮想勝ち時計83.57秒、前半600m35.52秒。結果を元にレース物理の係数を調整していない。
- レジストリのfail-closedゲート：芝外円盤1件以上または画像上の最大飛び2px/m超、画像未取得、コースID不整合の場合はスタートを無効化する。東京2000mは画像未確保なので安全に遮断。
- ブラウザ試験 GitHub Actions: lab-cross-course-kyoto-outer.yml（ChromeとWebKitの画像監査・18頭完走・全頭時計）。実行完了前は横展開合格としない。
- 台帳画面は race-lab-course-catalog-view-v1.html 。既存公式カタログから10競馬場／133コース距離・経路を取得し、基準LAB・試走・未検証を区別する。公式寸法があるだけでは自動的にプレイ可能にしない。

## 次の承認ゲート
Chrome/WebKitの原SVGマスク・全馬完走合格 → スマホ実機で芝帯・内ラチ・馬番の滑らかさの目視 → 京都外1400mを準承認へ移行。東京と他会場はベクター原図を入手・監査後に同じ共通処理を適用。STAGINGと正式予想・本番にはユーザー承認まで一切展開しない。

- source-derived safe corridor全区間に共通2.0元画像pxの境界余白を追加し、補間上に残るsubpixel透過境界は同じ緑帯の内側へ0.25px刻み最大3pxだけ吸収。5m→1m間隔、6レーンで8,406チェック。角・レース別の手修正なし。
- **実ブラウザ合格**：GitHub Actions #39290203147。Chrome/WebKit 390px双方、8406ポイントで芝帯外0、最悪1m表示移動 Chrome 1.727px / WebKit 1.479px（共通閾値2px以下）。プレイボタンready、架空18頭完走、600m通過、上位3頭の馬番・馬名、全馬時計・着差を確認。元SVG不変更。

## 2026-10-20 3・4コーナー内回り誤侵入の根本対策
- 旧版の8,406地点の緑帯監査は、外回りか内回りかの区別を付けていなかった。別の緑色コースへ移っても安全と誤判定する設計不足。
- 元うまぽっとSVGから**元の緑パスごとの図形ID**を読み取り、コース台帳に対応する original green path index を登録。京都外回りは元SVG緑パス #0 の外回り全周（個別の画像座標・コーナー補正ではない）。ブラウザは同じ原SVGからそのパスだけをオフスクリーンに描き、安全な領域との交差だけで走路を再算出する。**内回りの別パスの緑領域は外回りコース候補に絶対含めない**。
- 元SVGを置き換えたり上書きせず、正式走行エンジンは同一。どのコースも元原図の path ID と inner/outer layout だけが個別データ。コースID不一致・path不明・芝帯外・1m画像移動超過は従来通り起動停止。
- 右上の時計は京都外1400 pilotで PC 22px、スマホ20px、600m通過13/12pxに縮小。時計の時間計算・標準2倍速・全馬結果は不変更。
- Chrome / WebKitの実画面で **sourcePathIndices=[0]** / 園外円盤0 / 全馬完走 / 3・4コーナーの別原SVGパス混入0 を確認して初めて承認。旧1,686/8,406「緑色のみ」のテストでは外回り継続を証明できない。

## 2026-10-20 3C/4C内回りへの侵入（外回りトポロジー保証）
- 過去の source RGB緑画素判定のみでは、「外回りの走路」と「内回りの緑の走路」を識別できず、3〜4コーナーで内回り側へ大きく侵入する現象を見逃した。
- 今後は原SVGをリクエストし、図形の緑ストロークを**元のパス単位で別々の安全マスクに分ける**。京都外1400の原SVG外周パスは index 0。マスクは source PNG/SVGの実ピクセルとの交差部分のみで、原図は一切変更しない。
- コース固有のデータは sourceGreenPathIndices、原図出典、物理寸法のみ。画面上のレーン補正・タイム・数値再生エンジンは共通。
- CI Chrome/WebKit 390px（2026-10-20）双方成功： 8,406チェックで芝帯外0、outerOriginalSourcePath=[0]、maxProjectedStep約0.807/0.812px/m、全架空18頭ゴール・600m時計・上位3頭と全馬結果一致。
- 3/4コーナーの距離600/720/850/950mへ共通物理ステップで移動し、各距離の実況スクリーンショットをGitHub Actions成果物として保存するブラウザQAを追加。画像上の元SVG外周パス以外を選べば安全ゲート停止。
- 時計は京都外1400の実況ではスマホ20px・PC22pxへ縮小し、表示時刻はオリジナル物理計算のまま。
