# LAB v21 京都2000内回り：共通コース画像距離変換への切替・安全監査

日付 2026-10-19 JST

## 目的と非変更契約
ユーザーから「個別調整を続けると他のコースへの横展開が大変」と指摘。コースごとに「1270mだけ傾きを .62にする」などの特例は廃止。背景はうまぽっと原SVG `assets/kyoto-umapot-course-clean-v8.svg` **まったく変更しない**。すべての18馬番の元の走行メートル・レーン・速度・脚質・ゴール順・時計、京都1400と共通の`RaceSimEngine`/`RaceLaneAI`、JRA/NARの正式予想・買い目/PDF・staging・productionには変更なし。

## 共通モジュール
`RaceCourseImageGeometry.build` の入力は、`distanceM`, `anchorsM`, `pointAt(distance,lane)`（任意画像上の経路）、`lane`, 任意の`displayGain` のみ。
- 画像上の走行ラインを1m刻みで弧長積分。各公的メートル基準点を、元画像のまま完全固定。
- 各区間の速度・両側の最適化傾きは**全コース共通の加重調和平均と数値計算**。3コーナー固有の条件分岐、競馬場名、レースコースID、手指定スロープなし。
- 補正が画像上の総速度で逆行を生まないよう単調性を全区間で監査。30mの固定物理的二点間隔の画像上の急変を、全区間の同一損失関数で抑制。
- 旧方式は `?geometry=legacy` で復旧可能。ChromeとSafariともに画面操作・ゴールまで実証。
- オプション`?lens=off`は表示カメラの拡大だけを切り替える。画像上の馬番物理座標を変更しない（同じレンズ統計に基づき幾何モデルを構築）。

## 残課題
- 京都2000 LABは共通距離エンジン標準。しかし、元画像の芝帯輪郭を抽出する処理そのものは京都2000にある。抽出を汎用化するには、各コースの元画像、登録済みの内外ラチ、距離基準点が揃うことが前提。各場で固有の芝のつながり・白帯を越えない選択が必要。
- 1400/東京2000は**シャドーの数学・画像座標互換を確認したのみ**。運用中の元シミュレータの描画切替はユーザー承認・デグレ監査後。
- 3C見かけの伸びは約6.5%残存。元コース画像の形状を保持した平面俯瞰上では、元の弧長と画面の弦長の差はゼロにできない。残りをレース物理の変化と誤認しない。
- iPhone実機の見た目はまだユーザーの目視承認前。本番へ昇格禁止。
