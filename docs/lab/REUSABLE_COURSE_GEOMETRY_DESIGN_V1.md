# 競馬シミュレータ：横展開可能なコース描画契約 — 2026-10-19

## ユーザー指摘
京都2000mの3コーナー入口 1270〜1310m における隊列全体の見かけ上の急な伸張が解決していない。これを距離地点ごとの手動パラメータ（1270m専用 slope など）で調整し続ける方式では、他競馬場・他コースへの横展開コストが際限なく増える。**個別補正を正規設計として採用しない。**

## 絶対保持条件
1. うまぽっとの元SVGコース図は完全に不変。描き直し、画像引き伸ばし、芝・内ラチ改描、直線化した偽背景は禁止。
2. 京都1400と同じ `RaceSimEngine` と `RaceLaneAI` を走行物理の唯一の正本にする。
3. 馬番は実際の進行距離 d とレーン l に対応する元の芝帯位置を表示する。重なりを隠すため物理座標と無関係に動かさない。
4. LAB受入、実機目視承認の前に本番/ステージングへ反映しない。

## 確定した原因の具体例
同じ内レーンにいる先頭・最後尾について、1270〜1310m の**物理馬間差は29.4→27.69m（-1.71m）**なのに、SVG上の2点間の弦長×カメラ倍率は**約150.45→194.32画面px（+29.2%）**。体力・末脚・追走補正の急変ではなく、Illustrated SVG の進行距離登録の局所速度差と曲率が原因。従来の v19 の緩慢なカメラ倍率だけでは+29%の問題を解消できていない。

## 推奨する汎用実装
コースごとに許される差は背景素材と**最小限の公式幾何メタデータ**（スタート、ゴール、コース種別、内外回り、距離、内ラチ境界、確実な距離基準点、走行方向）だけにする。
- 元画像の内ラチ/外ラチの点列から閉じた芝帯内走行経路の **arclength パラメータ s** を構築。メートル d から s への変換を、全基準点が固定される単調関数として同時に求める。区間末端の直後にだけ急な倍率が生じないよう **速度・加速度の連続性**を全区間制約にする。基準点に人が数値調整した derivative やブレンド距離を追加することは禁止。
- 距離から元画像への座標投影 `position(d,lane)` はすべて同じモジュールで実施。共通の芝帯境界チェックを通す。
- カメラ表示は原図の**単一の平行移動＋等倍率拡大**だけ。物理的な馬群間隔・経路を不変にし、視覚的な隊列の急な拡大/縮小をコース全域で監査する。ただし曲線の弦長は弧長と一致しないため、2D原図維持と全ペア画面距離一定は同時には保証できない。
- 汎用QAは全コースを5m単位で監査し、基準点不変、元画像の一致、馬番円周の芝外0、映像前後位置逆行0、5〜10mの短区間で物理的な馬間差と見かけ上の伸縮が極端に乖離しないこと、開始〜ゴール終了のSafari再生をテストする。3コーナー以外でも警告する。

## 実装順序と承認ゲート
1. 既存京都2000 LABを比較用に凍結し、問題再現テスト（1270〜1310m で物理縮小なのに表示拡大すること）を汎用QAへ格納。
2. `CourseImageGeometry` 相当のコース独立なモジュールへ `sourceDistance` と芝帯評価を切り出し、データ差し替えだけで作動させる。
3. 京都2000で合格後、**京都1400・東京2000など別形状のコース**で同じ汎用コードを使い、地形固有パラメータの追加なしで通過することを確認。元画像や予想へ影響させない。
4. ユーザーiPhone実機承認のあと初めて他コースへ横展開。

## 現在の状態
3コーナー入口を改善できる候補が研究中だが、コース専用の slope 値（例 .62, .67, .72）をそのまま正式採用することは**見送り**。今回の記録は設計判断のみで、3コーナーの見た目の未解決を「完了」とみなさない。
