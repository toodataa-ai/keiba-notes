## v24 2026-10-20 等速時計と馬番の描画安定化
- 実出走馬17頭を固定seed 2026でシミュレートすると勝ち時計約115.38秒、1000m通過約57.09秒。レースの物理時計が極端に速いのではなく、初期選択2倍速が表示時計を実時間比2倍に進めた。既定1倍速へ修正、2倍/4倍は「早送り」と表示。競馬の能力・速度計算自体は変更しない。
- v20〜v23 の推測表示 `predictedD + exponential low-pass` は物理刻み更新の境界で微小なノコギリ状動作を引き起こし得るため、`RaceFrameInterpolator` の「前回物理確定姿勢と今回確定姿勢の線形補間」に変更。物理状態/競走結果/元SVGは不変。0.08秒の表示遅延のみで物理位置を先読みしない。
- `?motion=legacy` で旧式表示を選択できる。リセット/ジャンプ/出走馬切替では両フレームを同じ位置に初期化。
- 他競馬場の横展開ではコース別スロープ値・物理補正値を追加せず同一フレーム補間機構を適用。実機見た目はユーザー受け入れ前。

## v25追補｜ステップ刻みの一致
ブラウザ本再生は常に0.08秒刻み。旧地点ジャンプの0.12秒刻みは同じ固定シードでも0.08秒で結果と順位が変わる場合があったため、ジャンプ用の物理進行も共通`RaceFrameInterpolator.STEP_SECONDS`に合わせた。実17頭の完走回帰試験も、ユーザーが再生する刻みに統一。旧物理計算の式自体は変更していない。

## v25描画落ち対策
GitHub Chrome/WebKit 1.1秒の旧QAでWebKitが14フレームと低速となり、旧`30フレーム必須`判定が失敗。描画頻度が低い場合の描画時間差上限が0.06秒では2倍再生が実時間より遅くなるため、最大0.18秒・1回あたり12物理刻みまで追いつく変更を実施。速度評価は絶対フレーム移動幅ではなくフレーム間の単位時間あたり速度で監査し、WebKitの環境負荷によるフレーム枚数は10以上を許容。物理1刻みの0.08秒や進路ロジック、画像は変更なし。
