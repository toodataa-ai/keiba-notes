# 京都芝2000m内回り LAB v0.49 — 芝帯境界から自動内寄せ

## 改修内容
従来の手動距離別の画面補正を走行位置の正本にせず、**うまぽっと原画像の緑芝帯の内端・外端**を機械抽出する。芝帯の色を再解析し、5m刻み全401点の境界オフセットを数値JSONとして保持。画像そのものは再配布しない。注釈の線・文字で隠れた地点だけ隣接する境界を補間。座標は測量値ではない。

| 観点 | 処理 |
|---|---|
| 原画像 | [うまぽっと京都コース素材](https://umapot.com/?p=13277) |
| 境界抽出 | `tools/extract_turf_band_v1.py`。緑画素を検出し既存走行コースに近い芝帯を選択 |
| 計測解像度 | 5m（401地点）。直接検出385、遮蔽補間16 |
| 共通描画 | `RaceTurfCorridor.point(profile,d,lane,legacyPoint)`。実況と全体図は `RaceUmapotOverlay.point()` 経由で同じ座標を使用 |
| 横方向の配置 | 内ラチから `1.8m + lane * 1.65m`、芝幅はコース最低幅27mを利用。rを0.025〜0.975へ安全クランプ |
| 進路選択 | 京都1400と**同一の既存 RaceLaneAI** を利用。馬場形状の投影以外の時計・戦術・オッズ変更なし |
| 適用範囲 | 京都2000内回りだけ。画像境界データのない他コースは古い軌跡で維持し、勝手な他コース変更をしない |
| 実証 | 18頭・5m全区間・全レーン、390/1024pxのブラウザ撮影。外部画像読み込みが不可能ならLAB画面にエラーを出し代替画像を生成しない |

## 各コースへの横展開
各コースのオリジナル画像・既存の粗い走行順序を登録すれば、**同じ芝帯抽出器と位置変換器**を再利用できる。外回りと内回りが交差する箇所は「どの芝帯か」の識別が必要で、推定コースの形が実物と違えば画像上の色だけでは判断できない。その場合は公開保留として目視で受入れを行う。内寄せのピクセル値をコースごとに手で当て続ける方式には戻さない。

## 注意
LAB専用・非公式合成馬18頭の検証。現時点では精密なラチ測量保証なし、他コースへの自動承認なし。本番・STAGING・正式予想・買い目・発走前proof・PDFを改変しない。

## 他コースで同じ方式を使う方法
抽出器は `--course` でコースを選択できる（初期対象：`kyoto_turf_inner_2000`、`kyoto_turf_outer_1400`、`tokyo_turf_2000`）。例えば `python3 tools/extract_turf_band_v1.py --course kyoto_turf_outer_1400 --output /tmp/kyoto-outer-rails.json`。抽出結果にはコースID・外部原画像URL・内外境界を収録する。

**重要：他コースは抽出しただけでは自動採用しない。** 外回り・内回りの分岐、白い区分帯、注釈の遮蔽、元の仮登録線が別の芝帯を指していないかを検証し、人の目視承認後に各コースのLABデータへ登録する。既存の京都1400/東京2000の動きは承認まで不変。

## 元画像を使った直接色判定
`tools/audit_turf_band_pixels_v049.py` が芝帯内の代表レーン0/1/3/5/8/14を10m刻みで計1,206点監査した。緑画素への直接一致率はレーンごと95.5〜98.0%、周囲2pxを許容すると1,206/1,206点が緑色であった（GitHub Actions検証）。画像上の文字・補助線やアンチエイリアスで色が変わる場所を考慮している。
