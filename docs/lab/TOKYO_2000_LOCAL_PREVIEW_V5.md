# 東京芝2000m：原図連携・端末内評価再生 v5

状態：LAB限定／正式走路は未承認／目視承認待ち。STAGING・本番・正式予想に移行しない。

公開ページに原素材は含まれない。原図未読込では再生不可。
既存の `RaceTokyo2000.create()` は引き続き `TOKYO_ORIGINAL_ROUTE_UNVERIFIED` で停止する。
新しい原図連携候補のみ、端末内検査に合格したシードを評価再生する。

## 利用手順

1. [素材元・利用規約とローカル変換手順](TOKYO_2000_SOURCE_AUDIT_V2.md)に従い、原PPTXから `audit-local.json` と `source-local.svg` を生成する。原素材の転載は禁止再配布をしない。
2. LABページの「ローカル原図と走路候補の静止照合」を開き、2ファイルを一緒に選択する。静止読込だけでは走行できない。
3. シードを指定し「端末内で安全監査・再生を準備」を押す。ハッシュ、原図ベクターの芝帯・馬体四隅、走路折返し、共通エンジンの全18頭完走・余走とフレーム間安全性、同一シードの全フレーム再計算を検査する。
4. 合格時だけ「評価再生」が有効になる。1・2・4倍、停止、最初へ、指定地点の静止確認が可能。
5. シード変更・ファイル交換で合格状態を破棄する。未対応の変換SVGや不合格データは停止する。各馬の余走が原図監査範囲2120mを超えるシードも停止し、表示距離を範囲端へ切り詰めない。

ファイルはアップロード・永続保存しない。元PPTX・SVG・生成座標・原図入りスクリーンショットをGitHubやActions成果物に含めない。変換環境によりSVGのSHAが変わる場合、認識済みの変換結果でない限り評価再生はできない。

## 走行安全

v4の横速度上限1.2m/s・横加速度上限0.8m/s²を継承。原図連携候補では側方余裕を0.55mに拡張し、前後のクリアランスもその側方範囲にそろえた。単に横移動の向きの障害物だけを見ると、後方の速い馬が側方の停止領域へ進入し、共通LaneAIによる急停止を招くため。馬番・着順別の調整はない。既存v4候補は従来の0.35m余裕のまま。

32シード（1〜30, 2026, 2027）、固定80msステップで：

- 全18頭の完走・32m以上の余走：32/32。
- 活動中・ゴール付近・余走を含む検査矩形のフレーム間重なり0、レーン逸脱0、後退0、緊急横停止0。
- 最大横速度1.136m/s、1ステップの横速度変化最大0.064m/s。
- 40ms感度検査3シードでも安全項目0。刻み変更では着順が変わる場合があるため、再生速度は物理刻みを変更しない。

矩形は2.55m×0.8mのモデルで、実馬の衝突を保証する測量ではない。
原図ベクター上は0.25m刻み×17レーンの中心と馬体四隅を検査。72万885点で芝帯外0、数値ヤコビアンの反転0。元SVGの画素検査129万9699点も継続。

## 描画・カメラ・時計

原図のSVGパスを端末内でCanvasベクターへコンパイルし、同じCanvas・同じ等方変換で馬番を描画する。低画質JPEGの拡大や縦横別倍率の引き伸ばしはしない。原図全体は固定方向、実況は接線の向きと別管理し、右から左へ進むよう連続回転で追跡する。停止中はカメラを動かさない。実況の高さは京都と同じ380pxにそろえ、ゴール前16レーンの馬番円を白帯の内側に収める。

残り80mで京都最新版と共通のゴール演出へ切替。横幅100m、ゴール板30%、先頭は画面幅110%の位置から自然に進入。東京の左回りを実況向きへ流用しない。各馬の実際の `displayD` とレーンを使い、視認性のために距離や時計を変えない。

物理計算は固定80ms。1・2・4倍は同じ計算済み状態間の表示補間だけを変える。全18頭の余走を描画し、全馬ゴール後に上位3頭・全18頭の時計・秒差を表示。馬身差は共通HUDと同じくエンジンの通過時速度と時間差からの概算で、正式着差ではない。タブが非表示になったら停止する。
