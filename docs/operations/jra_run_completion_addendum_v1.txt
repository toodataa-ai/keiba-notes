JRA競馬予想・正式プロンプト必須実行補則 v1
【途中終了禁止・問題発生時のみ停止・成果物実物で完了判定】
適用範囲：GitHub正本 docs/data/latest_prompt.json から参照される全ての新規JRA正式予想実行。
優先順位：本補則は「実行の進め方と完了判定」のみに作用し、正式予想プロンプト v3.11 の予測方法、STEP1/STEP2、馬券最適化、着順分布、過去原本、PDFデザイン、法令・証跡条件を変更しない。
この補則は最新の正式プロンプトとセットで毎回必ず読み、適用の有無を監査すること。

■ [COMP-00] 原則：課題やエラーがなければ完遂する
ユーザーが指示した対象範囲を、途中の一作業が終わったこと、メッセージを返したこと、GitHub Actionsが成功したこと、指定された一部のファイルを作成したこと、長時間実行したことだけを理由に中断・終了してはならない。
実行可能で、具体的な課題・エラー・実行制約が発生していない限り、次の工程を継続する。
完了条件を満たすまで、通常の進捗報告は完了報告ではない。ユーザー不在を中断理由にしない。

■ [COMP-01] 実行範囲と順番
最初に対象日・開催場・レース・要求成果物・発走時刻・適用最新プロンプトを確定する。
対象範囲の全レースについて公式発走前情報の取得と根拠監査→STEP1の全頭能力・適性評価と印固定→STEP2の通常8券種と主要購入方式・結合着順確率・期待値/損失評価→最終購入判断/全final_bets固定→発走前snapshot/proof_commit→HTML/PDF生成→全ページ検品→GitHub保存→公開反映→公開実物の確認、という順序を守る。
発走後の追完予想・実オッズの創作・過去の結果に合わせたSTEP1やfinal_betsの変更を行わない。
各工程で対象の全レース/全馬/全券種/全買い目に対する既存の完了条件と対応する成果物を照合する。

■ [COMP-02] 完成・公開チェックリスト
1. 正式プロンプトと本補則および固定SHAが確認済み。
2. 対象全レースのSTEP1/STEP2と、発走前価格・出典・確率・最終買い目が既存基準で監査済み。
3. 予想原本の発走前snapshot/proof_commitとfinal_betsの一貫性が確認済み。
4. HTML/PDFに①〜⑨の評価色、1頭1ページ、全採用・不採用買い目と不採用理由、集合リスクが省略なく掲載済み。PDF総ページ数に上限を設けない。
5. PDFとJSON/HTMLの全件・ページ数・文字・配色・データ整合性を実物で検証済み。
6. GitHub Actionsの完了と、保存されたGitHubの実ファイル、公開manifest、公開サイトのHTTPレスポンス内容が整合している。Actionsの緑表示だけでは完了と判定しない。
7. 最終回答で対象全件の完了/未完了、保存先、証跡、検証結果を明記。未確認を確認済みと書かない。
これらが満たされる前は「全作業完了」「公開済みを検証した」と断定しない。
ただし正式原本の固定は既存の発走前時刻制約に従い、後から検査のために改竄しない。

■ [COMP-03] 失敗時の扱い
停止を許すのは具体的な阻害要因が発生したときに限る：公式発走前情報や必要な実オッズの検証不能、CI/生成/検品の実エラー、GitHubの競合・アクセス制限、発走時刻経過による合法な予想固定不可、時間/実行ツールの上限、明示承認が必要な仕様判断等。
問題が生じた場合は、可能かつ安全で効果が見込めるリトライ・代替手順を試せるが、同一失敗の無限再試行は禁止。復旧不能な状態を作業の進捗が鈍いというだけで創作しない。
問題が解消すれば残工程へ進み、具体的な阻害要因が残る場合は安全に停止して、失敗の工程、原因、変更済み/未変更ファイル、完了済み・未完了・再実行方法を報告する。
エラー時に未完成品を完成済みとして公開しない。発走前固定済みの証跡を隠す・消す・上書きしない。

■ [COMP-04] 進捗と継続
時間のかかる実行では進捗を適宜知らせる。ただし進捗報告で処理を打ち切らず、正常なら続く工程を実施する。
今回の作業の一部分が成功したことをもって、残りの明示要求をユーザーへ差し戻さない。依頼された対象の一部を意図せず省略せず、途中で新たな手動指示を求めない。
ユーザーへの途中連絡は作業中である旨と検証済み事実を区別し、完了判定を前倒ししない。
チャットから外部サービスで自動継続できると推測してはいけない。実際に起動したCI/自動処理の範囲だけを報告する。ツールが使えない場合は実行できたふりをしない。

■ [COMP-05] 非破壊と優先関係
既存のJRA旧予想・結果・回顧・proof・final_bets・発表済PDF・地方競馬Shadowのファイルを本補則によって変更しない。
新規実行の公式情報、発走前価格、印固定、当日確率、購入判断の要件を一切緩和しない。
『問題がなければ完遂』は安全条件の迂回やエラーの隠蔽を意味しない。
実行途中での承認不要な小修正や再描画は行えるが、既存の固定仕様を破る変更は承認または明示ブロッカーが必要。
