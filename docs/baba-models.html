Pilotをどう進化させるか

JRA 10競馬場 × 芝/ダートの20モデルを独立管理し、Pilot → Backtesting → Candidate → Validated の順に昇格させます。Stage単位でも検証状態を分け、Candidate生成までは自動化し、本番予想への接続は承認後だけ行います。

Stage A

Stage B
朝実測 → 発走時

朝実測・降雨・乾燥条件から、各レース時点のJRA公式「良/稍重/重/不良」を確率予測。発走時含水率を架空の正解値として扱いません。

昇格ルール

可視化ルール： 実測バックテストが存在する指標だけ表示します。「Baseline」は比較対象です。Stage A CandidateでもStage BがPilotなら、モデル全体はBacktestingのままです。

  1. Stage Aは複数年・独立サンプルでLOYO/時系列検証を行い、naive baselineより改善すること。
  2. Stage Bはレース時点のJRA公式馬場状態を教師ラベルにし、現行heuristicよりLog Loss/Brier Scoreを改善すること。
  3. 乾燥ケースだけでなく雨天・馬場変化ケースを別監査すること。
  4. 未来情報混入なし・再現可能なバックテストであること。
  5. Candidate → Validated、本番モデル置換は承認必須。

Data policy: JRA公式含水率は2018-07-27以降、クッション値は2020-09-11以降を基本母集団。京都は2023年再開後を現行レジームとして優先します。
