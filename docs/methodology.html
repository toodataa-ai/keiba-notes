01

「強い馬」と「買いたい馬」は、同じではない

STEP1とSTEP2を完全に分けるのは、予想の中に市場人気を逆流させないためです。

人気を見ながら能力評価した方が、世間の情報も使えて合理的では？

一見そう見えます。しかし人気を見てから能力を評価すると、「強いから人気なのか」「人気だから強く見えたのか」が分からなくなります。そこで本システムは、まずオッズを原則見ずに能力と適性を評価し、◎○▲△×を固定します。その後で初めて価格を見ます。

STEP1：能力・適性この条件で誰が強いか。オッズから切り離して判断。
印を固定◎○▲は価格を見ても変えない。能力判断の証拠を残す。
STEP2：価格・期待値強さに対してオッズが高いか低いか。買うかは別問題。
よくある混線
「この馬は人気薄だから面白い」を能力評価の根拠にすると、穴馬探しと能力判定が混ざります。本システムでは、人気薄の妙味はSTEP2で扱い、STEP1の強さの順番は守ります。
02

一頭の馬を、①〜⑨に分解する

「なんとなく強そう」を禁止するための分解です。ただし単純平均もしません。

① 斤量前走比、同斤量実績、世代差、牡牝差、脚質との相互作用。
② ペース・展開逃げ意思、ハナ競合、隊列、S/M/M-H/H、今回の脚の使い方。
③ 馬場・バイアス発走時馬場、時計速度、位置取り、進路を分離して評価。
④ ローテーション間隔、休み明け、消耗、距離変更、相手強化、遠征。
⑤ コース適性右左、坂、直線、コーナー、内外回り、枠と脚質。
⑥ 血統距離・馬場・瞬発力・持続力の補助証拠。実戦実績を優先。
⑦ 調教最終追い、1週前、ラップ、負荷、乗り込み、好走時比較。
⑧ 騎手格言だけでなく競馬場・走路・距離・脚質・馬質補正後成績。
⑨ 基礎能力クラス、相手、時計、再現性、不利耐性、今回条件外でも通用する強さ。

大切なのは、9項目を「各11.1%」で足すことではありません。例えば道悪の消耗戦なら③馬場と②展開の意味が増し、純粋な能力比較では⑨が中心になります。条件によって証拠の意味が変わるため、単純平均は禁止しています。

03

「稍重だから時計がかかる」とは限らない

馬場は公式4区分と、実際の走りやすさを分けて考えます。

同じ「稍重」なのに、なぜ高速決着の日と消耗戦の日があるのか？

含水量だけでは馬場の反発や傷み方を説明できないからです。そこで芝では、公式の良・稍重・重・不良に加えて、内部的に「高速乾燥型」「標準型」「高速湿潤型」「低反発湿潤型」「掘れ・荒れ型」を考えます。

STAGE A朝の状態を予測
前日含水率・降雨・気象から推定
→
OFFICIAL ANCHORJRA実測で更新
当日含水率・クッション値
→
STAGE B発走時へ更新
雨・乾燥時間・風・日照を反映
→
RACE-DAY EVIDENCE当日実戦で監査
時計・位置・進路を分離

さらに「高速＝前有利」とも決めません。時計速度、位置取り、進路を別変数として扱います。高速馬場でも差しが届く日はあり、低速馬場でも前が止まらない日はあります。

ここがポイント：馬場状態を1個のラベルに圧縮しないこと。水分、反発、走行による傷み、当日のレース傾向を分けることで、「稍重」の中身を読むことを目指します。
04

1分45秒0と1分45秒5。速い方が上とは限らない

時計は条件を揃えて初めて意味を持ちます。

競馬場、走路、距離、馬場、当日の時計速度、斤量、ペース、位置取り、相手関係が違う生時計をそのまま並べると、簡単に誤判定します。そのため本システムは「同条件直接実績」をまず抽出し、その上で近似条件をまとめた内部指標「類似条件Time Index」を使います。

生時計だけなら

A馬：東京芝1800m 1:44.8

B馬：中山芝1800m 1:45.4

→ A馬が0.6秒速い、と言いたくなる。

条件を分解すると

A馬：高速馬場・軽斤量・スロー

B馬：低速馬場・重斤量・前傾戦

→ B馬の方が内容的に高水準という可能性がある。

しかも「一度だけ速かった馬」より、近い条件で高い水準を複数回出した馬を重視します。ベスト値だけではなく、2番目、直近、直近3〜6走の代表値を見るのはそのためです。

05

上がり33.1秒を見ても、すぐには褒めない

補正上がり3F指数 ACI は、「その状況で期待以上の脚を使ったか」を見ます。

後方から上がり最速33.1秒の8着と、4角2番手から33.6秒の1着。末脚が強いのはどちら？

絶対時計だけでは答えられません。後方待機は道中で脚を温存しやすく、前で競馬した馬は早い段階から負荷を受けています。ACIは、同一レース内の上がり平均との差をロバストに標準化し、さらに4角位置による脚の温存差を補正して、末脚の「内容」を比較します。

考え方：
ACI ≒ レース内での相対上がり性能 ＋ 4角位置補正
代表値： 単発MAXではなく、原則として直近3走ACI中央値

さらに、競馬場・走路・距離帯によって、末脚に求められる性質が違うことも解釈します。現在は sharp_closing（鋭い末脚寄り）、balanced、sustained_position（位置・持続力寄り）の3タイプを使います。

重要：sustained_position ≠ 遅い上がりほど偉い
「上がりがかかるコースだから35秒台を高評価する」という意味ではありません。鋭い上がりの比重を下げ、前半の負荷を受けながら止まりにくかったか、位置を取りながら持続できたかを相対的に重く見る、という意味です。
バックテスト：ACI系の検証は2015〜2018年をfit、2019〜2021年を次走testとして、7,740レース・105,423走で実施。直近3走ACI中央値は次走Top3判別AUC 0.6611、ACI1位馬の次走勝率17.73%を記録しました。一方、コース需要型で機械的に置換する方式は悪化したため不採用にしています。
06

「気分屋」と言う前に、ばらつきを測る

馬の心理は推測せず、観測できるパフォーマンス変動を再現信頼度として扱います。

ピークは高いがムラが大きい

115 → 86 → 114 → 88 → 116 → 90

走れば強い。しかし今回その性能が出る確率には不確実性がある。

ピークは少し低いが安定

106 → 108 → 107 → 105 → 109 → 107

上限は前者に劣っても、本命としての再現性は高い可能性がある。

そこで「ピーク能力」「現在値」「再現信頼度」を分けます。重要なのは、ムラが大きいからといってピーク能力そのものを削らないことです。能力はある。しかし発揮確率に不確実性がある。この二つを混同しません。

検証で見えたこと：再現性高群のACI上位馬は次走3着内率44.76%、低群は36.97%。約7.8ポイントの差がありました。ただし勝率は完全な単調関係ではないため、再現信頼度を「勝つ確率」と同一視はしていません。
07

競馬は、一つの未来だけを予想すると脆い

馬場も展開も、当てる対象であると同時に「外れる可能性を持つ変数」です。

発走時馬場は「良100%」のように決め打ちせず、良・稍重・重・不良の確率を合計100%で持ちます。展開もS/M/M-H/Hで整理し、ハナ必須馬、番手可、譲歩可能性、競り合い確率を明示します。

例：発走時馬場予測
良 55% / 稍重 35% / 重 9% / 不良 1%
→ 本線は良でも、稍重シナリオを捨てない。

ここで大事なのが「未知＝不適性」にしないことです。初コース、初距離、初馬場は情報不足であって、弱い証拠ではありません。未知は主に再現信頼度へ反映し、経験がないだけで能力を大幅に下げないようにします。

現在の課題
馬場は確率分布まで進んでいますが、展開はまだ完全な確率シナリオモデルにはなっていません。将来的にはS 15% / M 45% / M-H 30% / H 10%のように複数展開を重み付けし、各馬の「展開ロバスト性」を測る余地があります。
08

◎だから買う、とは限らない

能力本線と期待値追加を二層に分けます。

Layer 1　能力本線

STEP1で高く評価した◎○▲を中心に、能力上位同士の組み合わせを検討します。価格だけを理由に能力上位を丸ごと消しません。

Layer 2　期待値追加

条件一致馬、反発候補、直接実績がある低人気馬など、能力評価に対して市場価格がズレている候補を追加します。

つまり、「最も勝つ可能性が高い馬」と「最も買いたい馬」は別です。◎が1.5倍なら能力評価は◎のままでも、単勝は見送ることがあります。逆に△でも価格が十分に高ければ、買い目の相手として価値が出ることがあります。

ただし、まだ「真のEVモデル」ではない
現状は想定勝率の厳密な校正モデルが未完成です。将来的に勝率・3着内率を校正できれば、EV = 推定確率 × オッズとして、馬連・ワイド・三連系までより定量的に評価できるようになります。
09

「結果を知ってから賢くなったAI」を防ぐ

E2E検証の主役は精度指標より、まず“発走前に予想が存在した証拠”です。

新しいプロンプトを過去レースに使って当たった。それで改善したと言える？

言い切れません。過去レースを知っているモデルが、結果を完全に忘れて再予想したことを証明するのは難しいからです。そこで正式比較では、レース前に予想ファイルをGitHubへ保存し、そのコミットSHAをproofとして固定します。

1. 同じ発走前情報比較する版に同じcutoffとソース集合を与える。
2. 版ごとに予想v3.0とv3.1をshadowで独立実行。
3. Git proof発走前コミットSHAで予想を凍結。
4. 結果を別結合予想ファイルは編集せず、結果だけ別ファイルで追加。
5. 同条件で採点命中・順位・Brier・ROI等を共通計算。
Grade A

prospective_strict。発走前Git proofあり。正式な版比較・改善根拠。

Grade B

historical_replay。過去レース後追い。研究材料には使うが昇格根拠には単独使用しない。

Synthetic

計算器やCIの動作確認専用。競馬成績には数えない。

さらに、各プロンプト版が参照するbase promptやACI profile等をGit blob SHAで固定したmanifestを持ちます。これにより、同じ「v3.1」という名前のまま依存ファイルだけ後から変わることも検出できます。

採点対象：◎勝率、◎3着内率、◎○▲のTop3捕捉、勝ち馬捕捉、STEP1順位、確率がある場合のBrier / Log Loss、馬場予測、展開予測、馬券ROI。ROIだけで優劣を決めないのも重要なルールです。
10

改善にも、暴走防止のルールがいる

一度外れたから新ルールを足す、を繰り返すと過学習します。

そこで週次改善はA/B/Cの承認クラスで管理しています。変更の大きさと証拠の強さを分け、弱い根拠で評価思想を変えないようにします。

A

自動承認

誤字、説明、監査強化、非破壊的な微調整、可視化。

B

条件付き自動

重み変更、新監査、モデル更新。複数レースやバックテスト等の再現性が必要。

C

人間承認

評価思想、STEP構造、大幅重み変更、トレードオフのある変更。

もう一つの原則は、「改善履歴は増やす。実行プロンプトは増やし続けない」です。同じ意味のルールは追記せず統合・置換し、旧版は履歴として残します。プロンプト自体が巨大化して重要ルールが埋もれるのを防ぎます。

改善サイクル
予想 → 発走前固定 → 結果 → 回顧 → 改善候補 → 証拠評価 → 新版 / no_change → 次レースで再検証
11

まだ解けていない問題も、公開する

完成した予想法ではなく、検証可能な研究プロジェクトとして扱っています。

① ①〜⑨から勝率への変換が未校正評価は精密でも、A+が勝率何%かはまだ統計的に固定されていません。これが次の大きな研究テーマです。
② 展開の確率分布が未完成S/M/M-H/Hは使っていますが、複数シナリオを確率加重するところまでは未完成です。
③ ACIは相対指標同一レース内での末脚比較には強い一方、弱いメンバー内の高ACIと強いメンバー内の高ACIを同じ絶対能力とはみなしません。Time Indexやクラス評価で補完しています。
④ 成長曲線の明示モデルが弱い特に2・3歳馬では「今の能力」だけでなく、能力がどの速度で伸びているかを別に捉える余地があります。
⑤ E2Eはデータを貯めている途中新しいGrade A比較は未来のレースでしか増やせません。20レース未満では「改善確認済み」とは判定しません。

弱点を隠さないのは、予想の信頼性を下げるためではありません。何が分かっていて、何がまだ仮説なのかを区別すること自体が、検証可能な予想の条件だと考えているからです。
