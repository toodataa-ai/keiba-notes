01

「強い馬」と「買いたい馬」は、同じではない

STEP1とSTEP2を完全に分けるのは、予想の中に市場人気を逆流させないためです。

人気を見ながら能力評価した方が、世間の情報も使えて合理的では？

一見そう見えます。しかし人気を見てから能力を評価すると、「強いから人気なのか」「人気だから強く見えたのか」が分からなくなります。そこで本システムは、まずオッズを原則見ずに能力と適性を評価し、◎○▲△×を固定します。その後で初めて価格を見ます。

STEP1：能力・適性この条件で誰が強いか。オッズから切り離して判断。
印を固定◎○▲は価格を見ても変えない。能力判断の証拠を残す。
STEP2：価格・期待値強さに対してオッズが高いか低いか。買うかは別問題。
よくある混線
「この馬は人気薄だから面白い」を能力評価の根拠にすると、穴馬探しと能力判定が混ざります。本システムでは、人気薄の妙味はSTEP2で扱い、STEP1の強さの順番は守ります。
02

一頭の馬を、①〜⑨に分解する

何をどの程度重視するのか。まず「役割」を図で確認し、その下で使うデータを見られます。

①〜⑨の重視のされ方

色は役割を区別するためのものです。赤が能力評価の中核、オレンジがルール上やや強め、青が条件依存、グレーが補助情報を示します。

能力の中核基礎的な強さ
⑨ 基礎能力・クラス

地力・直接実績・補正時計を中心に能力の土台を評価

やや強めルールに明記
① 斤量

前走からの負担重量差など、今回の再現性に注目

条件によって変動一律の優先順位なし
② 展開③ 馬場④ ローテ⑤ コース⑧ 騎手

雨・距離・ハナ争い・休養などで重要性が大きく変わる

補助的な根拠実戦実績を優先
② 血統③ 調教

未経験条件や現在の仕上がりを補足する

これは配点表ではありません。 正式ルールに①〜⑨の固定係数や割合はなく、色や配置も「⑨が①の何倍」などの数値を意味しません。②③④⑤⑧は条件次第で決定的な材料になり得ます。

①〜⑨は何のデータを見ている？

各項目を開くと、具体的な入力情報と評価への反映が確認できます。

①斤量やや強め

使うデータ：今回斤量、前走比、好走時の斤量、3歳と古馬の負担差、脚質や馬場との組み合わせ。

評価への反映：斤量差が今回の能力の再現性にどう影響するかを確認します。前走比+2kg以上などの負担増も、ピーク能力そのものを消す理由にはしません。

②ペース・展開条件で変動

使うデータ：逃げたい馬の数、ハナ争い、想定隊列、前半ラップ、スロー〜ハイペースの分岐。

評価への反映：想定した展開で持ち味を発揮できるか。逃げ馬が多いだけでハイペースと決めません。

③馬場・バイアス条件で変動

使うデータ：発走時の良・稍重・重・不良の確率、含水率、当日時計速度、位置取り・進路の有利不利。

評価への反映：今回の馬場で過去の能力を再現できるか。時計速度と前・差し有利は別に判断します。

④ローテーション条件で変動

使うデータ：レース間隔、休み明け、叩き何走目、距離変更、前走消耗、遠征、相手強化。

評価への反映：状態や条件の変化を確認。主に現在値と再現信頼度へ反映します。

⑤コース適性条件で変動

使うデータ：同場・同距離での直接実績、右左回り、坂、直線長、コーナー、枠と脚質の関係。

評価への反映：今回のコースで能力を発揮できるか。初コースは未知であり、不適性と決めません。

⑥血統補助材料

使うデータ：父・母父などの系統からみた距離、芝・ダート、馬場、瞬発力、持続力。

評価への反映：未経験条件を補足します。実戦の同条件成績を優先し、血統だけで最上位評価にしません。

⑦調教補助材料

使うデータ：最終追い、1週前の時計・ラップ、併せ馬、負荷、本数、過去好走時との比較。

評価への反映：現在の仕上がりと再現信頼度の補助情報。調教だけでピーク能力を上書きしません。

⑧騎手条件で変動

使うデータ：今回の競馬場・走路・距離・枠・脚質での実績、継続騎乗、条件付き騎手格言。

評価への反映：今回の馬・コースとの相性を確認。有名騎手という理由だけで加点しません。

⑨基礎能力・クラス能力評価の中核

使うデータ：対戦相手とクラス、着差、レース内容、補正した走破時計・上がり、直近3〜6走の再現性。

評価への反映：そもそもどれだけ強い馬なのか。今回の適性とは切り分け、過去の1回の自己ベストに依存しません。

例えば道悪の消耗戦なら②展開・③馬場の重要性が増し、芝直線1000mなら⑤コースと進路が重要になります。一方、全頭の能力の土台は⑨で確認します。9項目を単純平均することはありません。 時計の補正とTime Indexの詳しい説明は04章へ。
03

「稍重だから時計がかかる」とは限らない

馬場は公式4区分と、実際の走りやすさを分けて考えます。

同じ「稍重」なのに、なぜ高速決着の日と消耗戦の日があるのか？

含水量だけでは馬場の反発や傷み方を説明できないからです。そこで芝では、公式の良・稍重・重・不良に加えて、内部的に「高速乾燥型」「標準型」「高速湿潤型」「低反発湿潤型」「掘れ・荒れ型」を考えます。

STAGE A朝の状態を予測
前日含水率・降雨・気象から当日朝を推定する段階
→
OFFICIAL ANCHORJRA実測で更新
当日含水率・クッション値を基準点にする
→
STAGE B発走時へ更新
朝の実測から雨・乾燥時間・風・日照で発走時を推定
→
RACE-DAY EVIDENCE当日実戦で監査
時計・位置・進路を分離

さらに「高速＝前有利」とも決めません。時計速度、位置取り、進路を別変数として扱います。ここでいうバイアスは「その日の馬場で、どんな位置・進路・時計の出方が有利だったかという偏り」のことです。高速馬場でも差しが届く日はあり、低速馬場でも前が止まらない日はあります。

ここがポイント：馬場状態を1個のラベルに圧縮しないこと。水分、反発、走行による傷み、当日のレース傾向を分けることで、「稍重」の中身を読むことを目指します。
04

1分45秒0と1分45秒5。速い方が上とは限らない

時計は条件を揃えて初めて意味を持ちます。

競馬場、走路、距離、馬場、当日の時計速度、斤量、ペース、位置取り、相手関係が違う生時計をそのまま並べると、簡単に誤判定します。そのため本システムは「同条件直接実績」をまず抽出し、その上で近似条件をまとめた内部指標 「類似条件Time Index」 を使います。これは、条件差をならして「その走りがどの程度の水準だったか」を比較しやすくするための内部時計評価です。

生時計だけなら

A馬：東京芝1800m 1:44.8

B馬：中山芝1800m 1:45.4

→ A馬が0.6秒速い、と言いたくなる。

条件を分解すると

A馬：高速馬場・軽斤量・スロー

B馬：低速馬場・重斤量・前傾戦

→ B馬の方が内容的に高水準という可能性がある。

しかも「一度だけ速かった馬」より、近い条件で高い水準を複数回出した馬を重視します。ベスト値だけではなく、2番目、直近、直近3〜6走の代表値を見るのはそのためです。

05

上がり33.1秒を見ても、すぐには褒めない

ACI（Adjusted Closing Index / 補正上がり3F指数）は、「その状況で期待以上の脚を使ったか」を見る本プロジェクト独自の指標です。

後方から上がり最速33.1秒の8着と、4角2番手から33.6秒の1着。末脚が強いのはどちら？

絶対時計だけでは答えられません。後方待機は道中で脚を温存しやすく、前で競馬した馬は早い段階から負荷を受けています。ACIは、同一レース内の上がり平均との差を外れ値の影響を受けにくい方法で標準化し、さらに4角位置による脚の温存差を補正して、末脚の「内容」を比較します。

考え方：
ACI ≒ レース内での相対上がり性能 ＋ 4角位置補正
代表値： 単発MAXではなく、原則として直近3走ACI中央値

さらに、競馬場・走路・距離帯によって、末脚に求められる性質が違うことも解釈します。現在は sharp_closing（鋭い末脚寄り）、balanced（中間型）、sustained_position（位置・持続力寄り）の3タイプを使います。

重要：sustained_position ≠ 遅い上がりほど偉い
「上がりがかかるコースだから35秒台を高評価する」という意味ではありません。鋭い上がりの比重を下げ、前半の負荷を受けながら止まりにくかったか、位置を取りながら持続できたかを相対的に重く見る、という意味です。
バックテスト：ACI系の検証は2015〜2018年をfit（係数などを決める学習期間）、2019〜2021年をtest（学習に使わず性能を確かめる検証期間）として、7,740レース・105,423走で実施。直近3走ACI中央値は次走Top3判別 AUC 0.6611、ACI1位馬の次走勝率17.73%を記録しました。AUCは0.5前後ならランダムに近く、1.0に近いほど順位付けの識別力が高い指標です。一方、コース需要型で機械的に置換する方式は悪化したため不採用にしています。
06

「気分屋」と言う前に、ばらつきを測る

馬の心理は推測せず、観測できるパフォーマンス変動を再現信頼度として扱います。

ピークは高いがムラが大きい

115 → 86 → 114 → 88 → 116 → 90

走れば強い。しかし今回その性能が出る確率には不確実性がある。

ピークは少し低いが安定

106 → 108 → 107 → 105 → 109 → 107

上限は前者に劣っても、本命としての再現性は高い可能性がある。

そこで「ピーク能力」「現在値」「再現信頼度」を分けます。重要なのは、ムラが大きいからといってピーク能力そのものを削らないことです。能力はある。しかし発揮確率に不確実性がある。この二つを混同しません。

検証で見えたこと：再現性高群のACI上位馬は次走3着内率44.76%、低群は36.97%。約7.8ポイントの差がありました。ただし勝率は完全な単調関係ではないため、再現信頼度を「勝つ確率」と同一視はしていません。
07

競馬は、一つの未来だけを予想すると脆い

馬場も展開も、当てる対象であると同時に「外れる可能性を持つ変数」です。

発走時馬場は「良100%」のように決め打ちせず、良・稍重・重・不良の確率を合計100%で持ちます。展開もS/M/M-H/Hで整理し、ハナ必須馬、番手可、譲歩可能性、競り合い確率を明示します。

例：発走時馬場予測
良 55% / 稍重 35% / 重 9% / 不良 1%
→ 本線は良でも、稍重シナリオを捨てない。

ここで大事なのが「未知＝不適性」にしないことです。初コース、初距離、初馬場は情報不足であって、弱い証拠ではありません。未知は主に再現信頼度へ反映し、経験がないだけで能力を大幅に下げないようにします。

現在の課題
馬場は確率分布まで進んでいますが、展開はまだ完全な確率シナリオモデルにはなっていません。将来的にはS 15% / M 45% / M-H 30% / H 10%のように複数展開を重み付けし、各馬の「展開ロバスト性（展開が多少変わっても評価が崩れにくい度合い）」を測る余地があります。
08

◎だから買う、とは限らない

能力本線と期待値追加を二層に分けます。

Layer 1　能力本線

STEP1で高く評価した◎○▲を中心に、能力上位同士の組み合わせを検討します。価格だけを理由に能力上位を丸ごと消しません。

Layer 2　期待値追加

条件一致馬、反発候補、直接実績がある低人気馬など、能力評価に対して市場価格がズレている候補を追加します。

つまり、「最も勝つ可能性が高い馬」と「最も買いたい馬」は別です。◎が1.5倍なら能力評価は◎のままでも、単勝は見送ることがあります。逆に△でも価格が十分に高ければ、買い目の相手として価値が出ることがあります。

ただし、まだ「真のEVモデル」ではない
EV（Expected Value / 期待値）は、確率と配当を合わせた「長期的にどれくらい戻る見込みか」という考え方です。単勝なら概念上 推定勝率 × オッズ で見られ、1.0を上回れば理論上プラス期待です。現状は想定勝率の厳密な確率校正モデルが未完成なので、まだ完全な数理EVモデルではありません。
過去版v3.4の改良履歴：根拠から三連単の確率まで。WIN5は対象外で、通常8券種を評価します。①〜⑨の全頭評価、同条件の直接実績、相手関係、馬場・展開、追切の確認状況から各馬の勝率を設定し、全頭の分布と条件付き着順モデルから三連単などの的中確率を計算します。独立勝率の掛け算や、単勝オッズからの連系オッズ捏造はしません。前有利・差し有利等の感応度、実オッズ、損益分岐的中確率、期待倍率、出所と時刻、未校正リスクを並べて購入を決めます。一部の券種が未確認でも他券種まで一律見送りにせず、正当な根拠が不十分な候補だけを除外します。高い試算EVだけで購入を決めず、旧予想や成績も変更しません。
過去版v3.5の改良履歴：三連単にも対等な購入機会。v3.4までは券種ごと代表1点のみを比較していたため、◎→○→▲が割高なら、別順序が割安でも見落とす弱点がありました。v3.5では印を固定したあと、三連単の着順入替、三連複の組合せ違い、馬単の両順序など、根拠のある複数候補を8券種ごとに生成し、券種・組合せごとの実オッズ、的中確率の仮定・変動幅、損益分岐確率、レース条件の根拠を比較します。的中率が低い・未校正という理由だけで三連単を除外せず、条件と価格が見合えば最優先にできます。一方で高配当・計算上の高EVだけを根拠に購入しません。候補数や却下理由も表示し、旧予想とWIN5除外方針はそのまま維持します。
08A

一つの買い目ではなく、セット全体を評価する

◎の馬を当てることと、価値のある買い方を設計することは別の判断です。

三連単の的中率が低いなら、最初から買わない方がよい？

必ずしもそうではありません。三連単1点が割高でも、フォーメーション・2頭軸マルチ等の複数点なら的中範囲を広げられる場合があります。ただし点数を増やすほど投資額も増えます。そこで購入セット全体の期待純利益、少なくとも1点的中する確率、投資額を回収できない確率を分けて比較します。着順を同時に扱うモデルで集合の的中率を計算し、個々の的中確率を単純に足しません。

通常8券種で候補を検証

WIN5を除き、単勝・複勝・枠連・馬連・馬単・ワイド・三連複・三連単の単点や複数点購入を評価。BOX、軸流し、マルチ、フォーメーション等は、実際に買う馬番の集合へ展開して重複と点数を監査。完全に買わないBOXを完全BOXと偽って表示しません。

価格だけでも的中率だけでも決めない

モデルの高EV候補でも損失リスクを見ます。的中率が上がっても期待純利益が大きく下がるなら不採用。各買い目のオッズは実測に限定し、未校正の勝率や購入後のオッズ変動という不確実性を残します。

改良の道筋（過去版と現行版を区別）：v3.8〜v3.10では券種ごとの購入方式を拡張。v3.11では最大EVと、期待利益を一定水準守りながら的中範囲を広げる方式を比較。v3.12では8券種の実オッズと購入セットの照合を強化。v3.13では条件に合う単勝の金額を100円単位で調整する仕組みを正式化しました。現在の正式な購入確定は、これらを無条件に積み上げたものではなく、下記のv3.15購入専用ポリシーで行います。
通常の購入：最大3操作1操作にBOXや流しの複数点が入ることがあります。3操作＝3点ではありません。
中穴：別枠で最大1操作実測オッズ20倍以上100倍未満の候補を採否評価します。
大穴：別枠で最大1操作実測オッズ100倍以上かつ100円の的中払戻1万円以上の候補を採否評価します。
投資上限：1レース6,000円通常・中穴・大穴を合わせた総額で管理。現行v3.15の購入単位は100円、最大で計5操作です。

すべての券種や購入方法を採用するのではなく、比較・除外理由まで監査したうえで最終セットを確定します。探索アルゴリズムが厳密な大域最適解を保証するわけではありません。勝率の確率校正も完成途上です。現行購入ポリシーv3.15の原本を参照できます。

09

「結果を知ってから賢くなったAI」を防ぐ

E2E（End-to-End）検証は、情報収集→予想→買い目→結果→採点まで、予想システム全体を一本につないで検証する方法です。

新しいプロンプトを過去レースに使って当たった。それで改善したと言える？

言い切れません。過去レースを知っているモデルが、結果を完全に忘れて再予想したことを証明するのは難しいからです。そこで正式比較では、レース前に予想ファイルをGitHubへ保存し、そのコミットSHA（その時点の内容を一意に識別するID）をproofとして固定します。

1. 同じ発走前情報比較する版に同じcutoff（情報を使ってよい締切時刻）とソース集合を与える。
2. 版ごとに予想v3.0とv3.1をshadow（公式予想に影響しない並走評価）で独立実行。
3. Git proof発走前コミットSHAで予想を凍結し、「レース前に存在した」ことを証明。
4. 結果を別結合予想ファイルは編集せず、結果だけ別ファイルで追加。
5. 同条件で採点命中・順位・Brier Score・ROI等を共通計算。
Grade A

prospective_strict。未来のレースを本当に発走前に保存し、Git proofがあるもの。正式な版比較・改善根拠に使います。

Grade B

historical_replay。過去レースを発走前情報だけで後から再現したもの。研究材料には使いますが、モデルが結果を既知の可能性があるため単独では昇格根拠にしません。

Synthetic

人工データで計算器やCI（自動テスト）の動作を確認するもの。競馬成績には数えません。

さらに、各プロンプト版が参照するbase promptやACI profile等をGit blob SHAで固定したmanifestを持ちます。manifestは「この版がどのファイルの、どの内容を使ったか」を固定する部品表です。これにより、同じ「v3.1」という名前のまま依存ファイルだけ後から変わることも検出できます。

採点対象：◎勝率、◎3着内率、◎○▲のTop3捕捉、勝ち馬捕捉、STEP1順位、確率がある場合の Brier Score / Log Loss、馬場予測、展開予測、馬券ROI。Brier Scoreは確率予測のズレを測り低いほど良く、Log Lossは「自信満々の外れ」を強く罰する指標です。ROIだけで優劣を決めないのも重要なルールです。
09A

買える予想にするには、発走前の証拠が必要

能力評価、実行補助、購入確定の版は同じではありません。

STEP1 v3.13：能力・適性を固定

①〜⑨と◎○▲△×を原則オッズの影響から切り離して確定。買い目の都合で印を後から変えません。latest_prompt.jsonが示す予想本体の版です。

実行補助 v3.14：発売状況を区別

開催有無、公式出走情報、発売開始を確認。「まだ発売前」と「取得に失敗した」は別の状態として扱い、存在しない資料や倍率を捏造しません。

STEP2 v3.15：購入セットを固定

実際に取得した価格に基づく券種・方式・点数・金額とfinal_betsを発走前に確定。通常最大3操作＋中穴・大穴を監査し、予想本体v3.13とは別版として管理します。

1. 情報の時点をそろえるJRA公式発走前資料と対象馬の情報を確認し、後から公開された結果や払戻を混入させない。
2. オッズの鮮度を確認v3.15では購入確定前の最古オッズが原則10分以内、対象価格の収集幅が3分以内。未確認の価格は採用しない。
3. Git証跡に保存発走前のsnapshot・prediction・final_bets・proof_commitを固定し、結果で予想を書き換えられないようにする。
4. 公開結果を検品HTML・PDFの全ページ、購入方法の展開と金額、保存内容と実際の公開URLの一致まで確認する。
現時点の未自動化部分も開示
v3.14の収集からv3.15の正式購入確定までは、実行者が2段階の処理を連結する必要があります。リマインドやGitHub Actionsの緑表示だけで「最後まで完了」とは判断しません。公式根拠や価格に不足があれば、理由を示して未完了とします。

レース後の公式結果・払戻・回顧は別ファイルへ追記し、発走前prediction、評価、印、final_betsの原本は保持します。地方競馬Shadowは独立研究系で、JRA本線の成績や購入結果には混ぜません。

10

改善にも、暴走防止のルールがいる

一度外れたから新ルールを足す、を繰り返すと過学習します。

過学習とは、過去の特定レースに合わせすぎて、その過去には強いが新しいレースでは弱くなることです。そこで週次改善はA/B/Cの承認クラスで管理しています。変更の大きさと証拠の強さを分け、弱い根拠で評価思想を変えないようにします。

A

自動承認

誤字、説明、監査強化、非破壊的な微調整、可視化。

B

条件付き自動

重み変更、新監査、モデル更新。複数レースやバックテスト等の再現性が必要。

C

人間承認

評価思想、STEP構造、大幅重み変更、トレードオフのある変更。

混同注意：ここでいう改善承認の「A/B/C」と、前章のE2Eデータ品質「Grade A / Grade B」は別制度です。前者は変更してよいか、後者はその検証データをどこまで信頼できるかを表します。

もう一つの原則は、「改善履歴は増やす。実行プロンプトは増やし続けない」です。同じ意味のルールは追記せず統合・置換し、旧版は履歴として残します。プロンプト自体が巨大化して重要ルールが埋もれるのを防ぎます。

改善サイクル
予想 → 発走前固定 → 結果 → 回顧 → 改善候補 → 証拠評価 → 新版 / no_change（変更なし） → 次レースで再検証
11

まだ解けていない問題も、公開する

完成した予想法ではなく、検証可能な研究プロジェクトとして扱っています。

① ①〜⑨から勝率への変換が未校正評価は精密でも、A+が勝率何%かはまだ統計的に固定されていません。Calibration（確率校正）が次の大きな研究テーマです。
② 展開の確率分布が未完成S/M/M-H/Hは使っていますが、複数シナリオを確率加重するところまでは未完成です。
③ ACIは相対指標同一レース内での末脚比較には強い一方、弱いメンバー内の高ACIと強いメンバー内の高ACIを同じ絶対能力とはみなしません。Time Indexやクラス評価で補完しています。
④ 成長曲線の明示モデルが弱い特に2・3歳馬では「今の能力」だけでなく、能力がどの速度で伸びているかを別に捉える余地があります。
⑤ E2Eはデータを貯めている途中新しいGrade A比較は未来のレースでしか増やせません。20レース未満では「改善確認済み」とは判定しません。

弱点を隠さないのは、予想の信頼性を下げるためではありません。何が分かっていて、何がまだ仮説なのかを区別すること自体が、検証可能な予想の条件だと考えているからです。

12

用語集

このサイト独自の用語と、統計・AI・開発で使う言葉を、競馬ファン向けに短く整理します。

ACI

Adjusted Closing Index / 補正上がり3F指数。単純な上がり秒数ではなく、同一レース内の相対上がりと4角位置を補正して末脚の内容を見る、本プロジェクト独自指標。

Time Index

競馬場・距離・馬場・斤量・ペースなど条件差を考慮し、生時計をそのまま比べないための内部時計評価。ACIとは別物で、レース全体の走破性能を見る側。

AUC

順位付けの識別力を見る統計指標。ざっくり言えば「好走する馬を上に並べられているか」。0.5前後はランダムに近く、1.0に近いほど識別力が高い。

E2E

End-to-End。一部分だけでなく、情報収集→予想→買い目→結果→採点までシステム全体を通して検証すること。

cutoff

予想で使用してよい情報の締切時刻。たとえば「当日8:00 cutoff」なら、それより後に公開された情報は検証用予想へ入れない。

shadow予想

公式予想やユーザー向け買い目を変更せず、比較・研究のためだけに裏側で並走させる別バージョンの予想。

manifest

あるプロンプト版が、どの本体・設定・モデルを使ったかを固定する「部品表」。同じ版名の中身が後から変わることを防ぐ。

commit SHA / blob SHA

GitHub上の状態やファイル内容を一意に識別するID。発走前の予想をSHAで固定することで、後から書き換えた予想を同じものとして扱えなくする。

Brier Score

確率予測と実際の結果のズレを測る指標。低いほど良い。「勝率70%」のような確率が本当に妥当だったかを評価する。

Log Loss

確率予測の誤りを測る指標で、低いほど良い。特に「95%で勝つ」と強く言ったのに負けたような、自信過剰の外れを大きく罰する。

Calibration / 確率校正

「勝率20%と予測した馬が、長期的に本当に約20%勝つ」状態へ確率を整えること。印の精度と、確率の正しさは別問題。

EV / 期待値

Expected Value。確率と配当を組み合わせた長期的な見込み。単勝なら概念上「推定勝率 × オッズ」で考え、1.0超なら理論上プラス期待。

ROI / 回収率

Return on Investment。投資額に対して何%戻ったか。競馬では「払戻 ÷ 投資 × 100」。100%超ならその期間はプラス収支。

過学習

過去の特定事例に合わせすぎて、未知のレースへの適応力が落ちること。一度の外れごとに専用ルールを増やすと起こりやすい。

Grade A / Grade B

E2E検証データの信頼度区分。Grade Aは本当に発走前に保存された未来予想、Grade Bは過去レースの再現。改善承認のA/B/Cとは別制度。

S / M / M-H / H

想定ペース。S=スロー、M=平均、M-H=平均より速め、H=ハイペース。現状は主シナリオ表示が中心で、将来は確率分布化を検討。
