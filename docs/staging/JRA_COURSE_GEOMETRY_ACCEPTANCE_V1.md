# JRA競馬場コース型：幾何データ完成条件 v1

対象は全10競馬場・芝／ダートの平地競走。障害競走は対象外。

## 登録内容の区分

- **諸元登録済み**：JRA公表の回り方向、走路種別、施行距離、芝A/B/C/D別の一周距離・直線距離・幅員、最大高低差、特殊スタートを記録する。
- **走路作成待ち**：実寸での内・外ラチ、分岐・合流、スタート地点とゴール板、参照画像への位置合わせは未完了。この状態では走行不可。
- **ステージング試作**：既存の東京芝A2000m、京都芝A外1400mのみ。既存可視化を維持するが、別コースのテンプレートへ自動流用しない。承認済みの正確な実寸図とは扱わない。
- **走行可能**：以下の検査にすべて合格しており、版・根拠・ステージング承認を記録している。

## 実寸走行線データの必須要件

1. 各ルートの座標単位はメートルで、X/Yは同一縮尺。画面アスペクト比で走路を伸縮しない。
2. **芝とダートを別の物理走路**として保持。東京ダート1600m、新潟ダート1200m等の芝スタート区間は、進入と合流を明示する。
3. **内回り・外回りは別の走行線**とし、単なる左右への画像オフセットで代用しない。新潟の直線芝1000mも独立。
4. **外→内**の特殊コース（中山芝3200m、阪神芝3200m）は、分岐点・切替方向・合流点を持つ接続グラフとして扱う。
5. 各競馬場の芝A/B/C/Dは、対応するレール移動・幅員・一周距離を保持する。同一線の無検証コピーは禁止。
6. レース距離ごとにスタートゲート位置・ゲート向き・合流地点・ゴール板を保持する。単に「一周距離−施行距離」の位置を仮定しない。
7. 勾配・高低差はコースごとの実際の位置関係で表現し、芝の勾配をダートへ流用しない。
8. 内ラチから馬までの横方向距離はメートルから座標変換し、走路ごとの右・左回りを考慮。馬番が内回り・ダート・内馬場へ混入しないこと。
9. 補間曲線の接続点の位置・接線・速度は連続。最後の直線を全馬がゴール板まで駆け抜ける。
10. 実画像との位置合わせは、3・4コーナーの少なくとも10地点、分岐・合流点、ホームストレッチと各スタート地点を検品する。**芝の緑の画素上**だけでは合格にせず、白線や内外回りの間にある芝帯も識別する。
11. メートル換算した経路長、公式施行距離・一周距離・直線距離が整合すること。A/B/C/Dの差もチェックする。
12. 公式平面図は根拠・参照資料として保管し、模式図からの手トレースは「近似」と明記。GPS・測量値との精度を誇張しない。

## 当日のレースへのデータ適用

`{ venue, surface, layout, rail, distance_m, horses, trackCondition, ... }` を受け取る。

- `RaceCourseCatalog.resolve` で**一意なコース型ID**へ解決する。京都芝1400mのような内／外の両方がある施行条件では、`layout` を必須にする。
- 芝のA/B/C/Dが不明なら保留、未登録の施行距離や路線の入力も保留。
- `RaceCourseCatalog.bindRace` は走路ジオメトリーが未承認なら必ず `geometry_not_approved` を返す。**ユーザーの承認なしに近い形のコースで代走しない**。
- 承認済みの走路を得た後、`race_id`・出走馬・馬番・脚質・能力値・馬場を結びつける。正式予想、STEP1/STEP2、買い目・結果は変更しない。

## 検査・公開フロー

1. JRAコース平面図・公式データからルート図を作成（ライセンス確認。元画像の再配布はしない）。
2. 10場のルート内外分岐・各距離のゲート位置をステージングで登録。
3. 形状と画像が合うか人間の目視・計算の両面で検査し、既存の東京・京都レースを含めた回帰を実行。
4. 走路タイプ別に版・根拠・検品結果を記録。未合格の型は再生対象に含めない。
5. ステージング承認後のみ、対象コースの公開可否を判断する。本番UI変更は別途承認が必要。

## 根拠

JRA公式の各競馬場「コース紹介」：
`https://www.jra.go.jp/facilities/race/<venue_code>/course/`

現状の台帳：`race-course-catalog-v1.json`（10場、27基本走路、57レール別設定、297距離別テンプレート）。
既存の試作：東京芝A2000m、京都芝A外1400m。残る走路の実形状・発走地点は未検証。
